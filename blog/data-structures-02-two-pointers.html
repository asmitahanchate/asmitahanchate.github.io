Two Pointers: a reason to move

Asmita Hanchate· Nov 18, 2026· 6 min read· Two Pointers

Day 1 was about buying speed with memory: a hash table remembers what you've already seen, so you never have to scan the array twice. Today is almost the opposite move. When the array already has some structure, when it's sorted, or symmetric, you often don't need extra memory at all. You just need two pointers and a reason to move them.

The brute-force shape is the same nested loop as yesterday: check every pair. Two pointers kill the inner loop a different way. You put one index at each end of the array and walk them toward each other. The whole game is this: at every step, you have to be able to prove which pointer to move, and prove that moving it can't step over the answer. If you can't justify the move, the technique doesn't apply.

01Valid Palindrome

LeetCode 125 · the shape in its simplest form

A palindrome reads the same forwards and backwards, ignoring case and punctuation. There are two honest ways to check it, and comparing them is the whole point.

The first is the one you'd write without thinking: strip the string down to lowercase alphanumerics, then compare it to its own reverse.

class Solution:
    def isPalindrome(self, s: str) -> bool:
        cleaned = [c.lower() for c in s if c.isalnum()]
        return cleaned == cleaned[::-1]
Time O(n)Space O(n)

Clean and readable, but it builds a second reversed copy, so it costs O(n) extra space. The two-pointer version spends nothing: put one index at each end and march them inward, comparing as you go, and bail the instant they disagree.

class Solution:
    def isPalindrome(self, s: str) -> bool:
        cleaned = [c.lower() for c in s if c.isalnum()]
        left, right = 0, len(cleaned) - 1
        while left < right:
            if cleaned[left] != cleaned[right]:
                return False
            left += 1
            right -= 1
        return True
Time O(n)Space O(n) cleaned · O(1) if you skip in place

This is the version worth internalizing, because the shape (two indices marching toward the middle) is the pattern. And if you skip the non-alphanumeric characters directly on the original string instead of pre-cleaning it, the extra copy disappears and it's genuinely O(1) space.

02Two Sum II

LeetCode 167 · when the input is sorted, remembering is wasteful

Here's a nice callback. Yesterday's Two Sum used a hash map because the array was unsorted, so I had to remember every number I'd passed. This version hands me a sorted array, and that one word changes the whole tool.

Put left at the smallest number and right at the largest, and look at their sum. If it's exactly the target, done. If it's too big, the only way to get smaller is to pull right down. If it's too small, push left up. No map, no second copy.

class Solution:
    def twoSum(self, numbers: List[int], target: int) -> List[int]:
        left, right = 0, len(numbers) - 1
        while left < right:
            total = numbers[left] + numbers[right]
            if total == target:
                return [left + 1, right + 1]     # the answer is 1-indexed
            elif total > target:
                right -= 1
            else:
                left += 1
Time O(n)Space O(1)

The sorted order is exactly what makes each move provable. When the sum is too big, every pair that keeps the current right with an even larger left is also too big, so I can drop right entirely and never look back. Same problem as yesterday, different structure in the input, a completely different tool. That contrast is the thing I actually want to remember.

03Container With Most Water

LeetCode 11 · the move that looks greedy but is provably safe

Each number is the height of a vertical wall. Pick two walls; the water they hold is the width between them times the shorter of the two heights. Find the pair that holds the most.

Start as wide as possible, a pointer at each end. Then the one move that makes this whole problem collapse: always advance the pointer at the shorter wall.

class Solution:
    def maxArea(self, heights: List[int]) -> int:
        left, right = 0, len(heights) - 1
        best = 0
        while left < right:
            area = (right - left) * min(heights[left], heights[right])
            best = max(best, area)
            if heights[left] < heights[right]:
                left += 1
            else:
                right -= 1
        return best
Time O(n)Space O(1)

Why is it safe to walk away from the shorter wall? The area is capped by that shorter wall. If I instead moved the taller wall inward, the width shrinks and the height is still capped by the same short wall, so the area can only stay equal or get worse. Moving the shorter wall is the only move that could ever find something better, so that's the move I make. Every pair I skip is a pair I've just proven can't beat what I already have.

The pattern, in one sentence

When the array is sorted or symmetric, replace the nested loop with two pointers converging from the ends, and make every step a small proof: moving this pointer cannot step over a better answer. Comparing from both ends wants a palindrome walk. A target sum in sorted data wants converging pointers. Maximizing over a pair wants you to abandon whichever side is holding you back.

Why I'm writing this one down

Day 1's skill was noticing when to remember. Day 2's skill is narrower and, honestly, a little harder: justifying the move. The code for all three of these is tiny. The entire difficulty lives in one sentence, "which pointer do I move, and how do I know I'm not skipping a better pair?" Once I can say that sentence out loud for a problem, the code more or less writes itself.
